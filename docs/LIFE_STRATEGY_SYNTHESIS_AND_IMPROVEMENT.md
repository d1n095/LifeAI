# LIFE STRATEGY SYNTHESIS & IMPROVEMENT LEARNING

## Purpose

Life learns methods, not winners. This foundation records how a new candidate work
strategy is assembled from existing, canonical evidence without activating that strategy
or changing production policy.

A synthesis case is a bounded proposal. It references existing work strategies,
executions, evidence, ideas, comparisons, experiments, Engineering Lessons, problem
components, assumptions, specialist contributions, navigation observations and stopping
decisions. It never copies or replaces those records.

## Deterministic flow

The supported flow is:

1. create a versioned synthesis case with explicit purpose and quality invariants;
2. add strictly validated, owner-scoped canonical inputs;
3. record ordered recipe components and their included, excluded, modified, alternative,
   deferred or unknown disposition;
4. record and resolve explicit component or assumption conflicts;
5. materialize a new candidate through the existing `work_strategies` registry;
6. evaluate it through existing 0043 verification and 0044 experiment, comparison,
   quality-gate and promotion-candidate records.

Materialization is not activation. Component support is not candidate verification, and a
promotion candidate cannot be bypassed by synthesis.

## Principles

- Useful ideas survive even when their parent execution or strategy loses.
- Strong executions may still contain unsafe or wasteful components that are excluded.
- Candidate strategies may combine methods learned from Claude, Codex, Life, local
  models, deterministic tools, founder corrections and future specialists.
- Provider/model attribution and method quality remain separate dimensions. There is no
  permanent best model or strategy.
- Component-level provenance records exactly where a method came from, why it was used,
  its evidence, assumptions, modifications and unresolved conflicts.
- Combining individually useful components creates new interaction risk and therefore
  requires fresh execution and verification.
- Correctness, safety, scope adherence, completeness, reproducibility and maintainability
  precede efficiency. Faster matters only inside a verified quality-safe envelope.
- Repository search and navigation are learnable methods. Recipes can encode ordered
  symbol, schema, caller, test, migration and history inspection with explicit stopping
  conditions, but this layer performs no semantic search.
- Failed synthesized candidates remain auditable learning evidence. Failure does not
  automatically invalidate every source component.
- Strategy revisions, predecessors, recipes, conflicts, materializations and later
  evaluations remain versioned and queryable.
- Engineering Lessons remain the sole reusable lesson store; synthesis only links to it.
- All recording, validation, materialization and explainability work without any AI
  provider, embeddings or external API.
- No synthesized strategy silently modifies Life Core or production behavior.

## Security and history

All synthesis records are owner-scoped and protected by forced row-level security.
Owner-aware foreign keys prevent privileged cross-owner linkage where the referenced
record is owner-owned. The heterogeneous input vocabulary is closed and each input must
populate exactly the matching canonical foreign key. Append-only inputs, materializations,
evaluation links, lesson links and events preserve evidence history. Guarded state changes
and row locking make replay and ordering deterministic.

Explainability is bounded and cycle-safe. It exposes predecessor cases, ordered
components, canonical inputs, conflicts, materialization, evaluation links, lesson links
and readiness blockers without generating an opaque model explanation.

## Explicitly deferred

- automatic LLM-generated synthesis;
- automatic component or assumption extraction;
- autonomous experiment scheduling;
- automatic candidate activation or production promotion;
- autonomous provider routing or team composition;
- automatic exploration/exploitation scheduling;
- semantic or generated code search;
- reinforcement-style policy updates;
- automatic strategy synthesis or conflict resolution;
- world-model planning;
- unrestricted self-modification;
- autonomous Life Core code mutation.
