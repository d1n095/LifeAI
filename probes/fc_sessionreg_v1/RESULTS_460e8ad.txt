WHAT THIS GATE IS
====================================================================================
An independent regression gate that encodes the REQUIRED invariant exposed by Priority 8:

  Every session-gated authority helper must treat a session invalidated by ANY real revocation
  primitive (revoked_at set / sessions_valid_after bumped / expired) as NOT current, regardless
  of sub-second truncation, with timestamp semantics consistent with the access-token iat check.

RG1/RG2/RG3 assert that REQUIRED behaviour for account_erasure_receipt_session_current (0086).
They are pytest.mark.xfail(strict=True) keyed to the confirmed Priority-8 defect:

  * on the current (UNFIXED) build they FAIL and are reported as XFAIL (expected-fail) -> the
    suite exits green, documenting the defect without a permanently red bar;
  * the moment the one-line fix lands (add `AND rt.revoked_at IS NULL`, align the freshness
    comparison), the required assertion starts PASSING -> strict xfail turns the XPASS into a
    FAILURE -> the loud signal to drop the xfail marker and enforce the gate as a hard pass.

RG4/RG5/RG6 are plain PASS invariant-locks on the CORRECT pattern the codebase already ships,
so a future change cannot silently regress them:

  * RG4/RG5 -- personal_recall_founder_authority_current (0083) already checks revoked_at +
    expires_at + created_at>sessions_valid_after and correctly rejects a same-second-reset-revoked
    session and an expired session. This is the exact pattern the erasure helper must match.
  * RG6 -- revoke_current_founder_sessions (0095), a privileged session-gated effect, refuses a
    revoked session ('live canonical Founder session required for session revocation'): the
    privileged-effect surface's session semantics are already consistent and fail-closed.
