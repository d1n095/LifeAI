## New defects (severity · owner)
- **SELECTOR-ASSIGN-NAMESPACE (P2 · Cursor/MainAI) — DELEGATE-WIRING NOT genuinely closed:** when a
  real workforce agent matches the capability, `select_best_candidate` returns its workforce
  `agent_key` (e.g. `research-strong`), which `service.assign` then **rejects** as *"unknown agent
  identity"* — the coordination ledger accepts only known recipients (cursor/claude/codex). So wiring
  the real selector **breaks the tick** (`outcome=assign_rejected`); the cycle only reaches a
  completed tick when the selector **fails** (`SelectorError`) and falls back to the hardcoded
  `CAPABILITY_TO_AGENT` default (`cursor`). **Capability-based delegation through existing workforce
  services is therefore not functional end-to-end in #314.** Proven: D1 (`assign_rejected` /
  "unknown agent identity" with seeded agents), D2 (completes only on the capability-default fallback).
  Fix: map the selected workforce `agent_key` to a valid coordination recipient (or register workforce
  agents as recipients) before `service.assign`.
- **DELEGATE-BROKER-BYPASS (P2 · Cursor/MainAI):** even on the fallback path the cycle mints via
  `service.assign` (coordination ledger), never `workforce.broker.resolve_delegation`. The broker's
  task-scoped authority, context secret-denial and `BUILDER_CANNOT_SELF_VERIFY` packaging (all real
  and acceptance-passing in `autoloop_v1`) are **skipped** — no `WorkforceContextPackage` /
  `WorkforceAssignment` is created for a tick. The composed cycle does not route delegation through
  the workforce services it claims to use.
